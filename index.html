Why a common engineer

Clover, the framework I wrote, opens with the common clover. Three leaves. It is the one growing in every field, and it is how nearly everyone works with AI today.

I am a common engineer in exactly that sense. I am the most ordinary person you are likely to meet, the neighbour you would not look at twice, and I am not saying that to be modest. Running in production

Answers when nobody is left to answer

New listings stopped appearing after repeated loads. The team that built the sync had left, and thousands of per-organization mappings were never written down. Working backward from what the customer saw, through read-only access to the systems themselves, found one misconfigured flag between ingestion and the database. A separate case — saved favourites showing on desktop but not mobile, caused by an email relay quietly creating a second account — had been passed between teams without an owner, and was answered the same way. Neither answer needed the people who built it.

Running in production

Composable content architecture

Pages built from reusable, independently governed sections instead of hand-made templates, so a new page ships without a code change. 50 published pages across 8 page types run on it. Permitted nesting, layout variants and required fields are enforced by the content model rather than by review, so a marketing team composes freely and still lands inside brand standards.

Parity harness and QA sign-off · not yet cut over

An API migration estimated at 8–10 weeks

GraphQL to REST, .NET 9 MVC to .NET 10 Minimal APIs. Around 7,800 lines across more than 200 files, with every route, JSON shape and response envelope preserved so no consumer had to change. Execution took about a day. Validation took another, agreement to ship took longer than both, and the work was not continuous.

The speed is the least interesting part. A harness compared the new API byte for byte against live traffic across 36 endpoint cases, and both versions ran side by side with the gateway pointed at the new one so QA signed off on the real site. What limits work like this is having an objective way to check it, not people.

Fix validated under load · upstream PR open, not merged

A memory leak followed past its workaround

Out-of-memory crashes in production were stopped first with a blunt Node flag, which also stripped error-stack detail across the whole application. The investigation carried on past that, through load testing and heap snapshots, into React's Server Components renderer. The root cause came down to a one-file change, contributed upstream so other applications need not carry the same flag. The mitigation it replaces was checked against a fleet running the same image: 113 restarts without the flag, zero with it, over about six and a half hours.

Clover

An AI Orchestration Framework

Clover connects real-world Context, human Direction, AI-driven Action and validated Success into a repeatable cycle. It sits on top of the systems a team already runs, so there is nothing to install and nothing to migrate onto.

The common way of working runs Direction, Action, Success. Context is only whatever the human remembers to hand over, so it turns up because the direction asked for it. Clover puts Context first, because the systems are already running before anyone asks for anything. Reality exists before the request. Context therefore comes before Direction.

  • ContextThe systems the organization already runs.
  • DirectionThe human sets the outcome and the boundaries.
  • ActionAI works out how, and does it inside them.
  • SuccessThe real environment shows the intended outcome.

I wrote it down and made it open because a way of working that only one person understands does not change how a team works. Every claim on it says what was checked, what was observed and where it stopped, including the parts that are unfinished.
