Profile

I have spent the last ten years building and working on software systems. Some were built from the ground up, some were systems that had to be changed without breaking what already worked, and some were systems that were failing and needed to be understood before they could be fixed. The work has covered architecture, distributed systems, APIs, cloud platforms, production debugging, and engineering teams.

As an Engineering Lead, the work is not only about the system. It is also about the people working on it: giving engineers enough context to make good decisions, reviewing designs and code, helping teams work through difficult problems, and keeping technical direction connected to what the business needs.

More recently, AI has become part of that engineering work. It can help understand a system, investigate a problem, write and change code, test what was changed, and work across information that would otherwise take much longer to bring together. The engineering responsibility does not move with it. The system still has to show whether the work produced the outcome that was intended.

  • Recurring out-of-memory failures were investigated using load testing, heap snapshots, production evidence, and AI-assisted analysis instead of stopping at an operational mitigation.
  • The investigation traced the failure into React Server Components rendering and reduced the change to a single-file fix. The fix was contributed upstream to React with a public reproduction.
  • Under sustained load, the same image restarted 113 times without the flag and zero times with it, providing a measurable check of the mitigation.

Production Data Problem

Engineering Principles

Understand before fixing. Know enough about the system to understand what is actually wrong before deciding how to change it.

Focus over parallelism. More work happening at the same time does not necessarily mean more progress.

Prove outcomes, not activity. Completing the work is not the same as achieving the outcome. The system has to show what actually happened.

Design for adoption. A capability that remains with one person does not change how the team works.
